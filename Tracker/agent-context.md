# Agent Context

## Роли чатов

- `Head` — главный чат. Формулирует задачи, принимает решения, сверяет backlog, делает финальную сборку смысла.
- `Frontend / UX` — интерфейс, формы, таблицы, модалки, визуальное поведение, клиентские тесты UI.
- `Backend / workflow` — API, статусы, права, workflow, история, уведомления, миграции и seed-данные.
- `Tests / regression` — Playwright, API regression, smoke/full прогон, шаблоны ручного тестирования.

## Маршрутизация

- UI, верстка, поведение таблиц, формы заявок, модалки, Excel-export: `Frontend / UX`.
- Статусы заявок, переходы workflow, права, история, уведомления, ошибки backend: `Backend / workflow`.
- Автотесты, регрессии, ручные тест-планы, тестовые данные: `Tests / regression`.
- Разбор приоритетов, постановка задач, приемка, коммиты и координация: `Head`.

## Текущие продуктовые договоренности

- В UI не используем термин `шлюз`; бизнес-термин — `исключение`.
- `PENDING_GATE` отображается как `Требует исключения`.
- Действия: `Разрешить исключение`, `Отклонить исключение`, `Исключение из регламента`.
- `Подвесить` заменено на `Отложить`; заявка в таком состоянии называется `Отложенная`.
- Колонка согласования показывает статус, переходы выполняются через действия.
- Открытие карточки заявки выполняется через кликабельный номер заявки, не через всю строку.
- Вложенные значения в таблицах показываются в одной ячейке с разделителем; где нужно, работают переносы по словам.
- В формах заявки используется широкая горизонтальная компоновка под экран 1366 px.

## Технические договоренности

- Runtime frontend должен обращаться к API через относительный `/api/v1`, без hardcoded `localhost` или `127.0.0.1`.
- Для сетевого доступа к dev frontend используется адрес вида `http://<host-ip>:5173`.
- Если frontend раздается не через Vite dev proxy, нужен reverse proxy для `/api/v1` на backend.
- Кодировки не чинить массовыми shell-заменами. Для ручных правок использовать `apply_patch`, для механических UTF-8-операций — аккуратные скрипты с проверкой.
- Сгенерированные отчеты Playwright не коммитить без отдельной команды.

## Передача между чатами

В конце работы рабочий чат обновляет:

- `Tracker/backlog.md` — статус задачи;
- `Tracker/handoff.md` — короткая запись: что сделал, чем проверил, что осталось;
- при необходимости `Tracker/current.md` — если изменился текущий фокус проекта.
